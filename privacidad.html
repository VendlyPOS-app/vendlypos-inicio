Política de Privacidad

Última actualización: 23 de septiembre de 2026

Esta Política de Privacidad describe de forma transparente y completa cómo la plataforma y suite de software VendlyPOS en sus ediciones para Windows Desktop y Android Mobile (en adelante, «la Aplicación» o «el Sistema»), desarrollada por NexoBits, recopila, usa, almacena y protege la información de sus usuarios. VendlyPOS es una solución de punto de venta (POS) empresarial (B2B) orientada a la gestión comercial local de tiendas y comercios.

Al instalar o usar la Aplicación en cualquiera de sus plataformas, el operador del negocio (en adelante, «usuario») declara haber leído y aceptado íntegramente esta Política. Si no está de acuerdo, debe abstenerse de usar y desinstalar la Aplicación.

Resumen rápido: VendlyPOS no vende, comparte ni monetiza datos personales o comerciales. Toda la información operativa de ventas, inventario, productos y clientes permanece en el dispositivo del usuario (SQLite). Se contacta con Firebase para validar la licencia de uso, opcionalmente con el Ministerio de Hacienda de El Salvador para la emisión de Documentos Tributarios Electrónicos (DTE), y opcionalmente con los servicios de Google (Google Drive y Google Identity) únicamente bajo autorización explícita para copias de seguridad en la nube y validación administrativa de catálogo web.

1. Información que Recopilamos

A. Datos operacionales del negocio (almacenados únicamente en el dispositivo)

La Aplicación opera de forma descentralizada y local mediante motores SQLite optimizados: Drift en la edición móvil para Android y SQLAlchemy con base de datos local (store.db) en la edición para Windows Desktop. Se almacenan exclusivamente en el dispositivo o equipo del usuario:

  • Catálogo de productos: nombres, precios, códigos de barras, categorías e inventario físico.
  • Historial de transacciones de venta: marcas de tiempo, totales, desglose de artículos y métodos de pago.
  • Datos de clientes del negocio gestionados por el propio comercio: nombre, teléfono, correo electrónico y puntos de fidelidad. Estos datos son ingresados manualmente por el operador y se almacenan localmente. En caso de emitir un DTE (Factura o CCF), los datos del receptor se transmiten al Ministerio de Hacienda de El Salvador como parte del comprobante fiscal; véase la sección D.
  • Configuración del sistema: nombre del negocio, parámetros de impresoras de tickets y ajustes generales.

B. Identificador de dispositivo para licencias (device_uuid)

Para gestionar y validar la licencia de uso, la Aplicación genera un identificador único de dispositivo (device_uuid). Este identificador:

  • Se genera mediante un hash SHA-256 con sal aplicado sobre información del dispositivo, con el fin de proteger la identidad física real del hardware.
  • Se almacena de forma cifrada en el almacenamiento seguro del sistema operativo (FlutterSecureStorage).
  • Se comparte con el servidor de licencias de Firebase exclusivamente para verificar que la licencia adquirida sea válida y no esté siendo utilizada en más dispositivos de los permitidos.
  • No se utiliza para rastrear al usuario, mostrar publicidad ni con ningún otro fin.

C. Datos de diagnóstico (Firebase)

La Aplicación usa Firebase (Google LLC) como infraestructura de gestión de licencias. Firebase puede recopilar automáticamente métricas de diagnóstico técnico del dispositivo (modelo, versión de Android, idioma) según la Política de Privacidad de Google. Estos datos son procesados por Google y no son accesibles para NexoBits más allá de lo que expone la consola de Firebase.

D. Credenciales y Datos para Documentos Tributarios Electrónicos (DTE)

La Aplicación incluye una funcionalidad opcional para la emisión de Documentos Tributarios Electrónicos (DTE) conforme a la normativa del Ministerio de Hacienda de El Salvador. Esta funcionalidad es de configuración voluntaria por parte del operador del negocio y únicamente se activa cuando el usuario ingresa sus credenciales.

Cuando se habilita el módulo DTE, la Aplicación gestiona los siguientes datos:

  • Credenciales del API del Ministerio de Hacienda (usuario y contraseña API proporcionados por el propio usuario): Se almacenan de forma cifrada en el Android Keystore del dispositivo mediante FlutterSecureStorage. Se usan exclusivamente para obtener un token JWT de autenticación ante el servidor del MH. No se comparten con terceros distintos al MH.
  • Clave Privada RSA (formato PEM): Generada por el operador con herramientas externas (ej. OpenSSL) e ingresada por el usuario. Se almacena cifrada en el Keystore de Android y se utiliza únicamente de forma local, dentro del dispositivo, para firmar digitalmente los DTE (firma JWS RS256). Esta clave nunca abandona el dispositivo.
  • Datos del receptor del DTE (nombre, NIT/DUI, NRC, dirección, correo del cliente del negocio): Se envían al servidor oficial del Ministerio de Hacienda (api.dtes.mh.gob.sv) únicamente como parte del documento fiscal, mediante conexión cifrada HTTPS/TLS. La Aplicación no retiene estos datos en servidores propios.
  • Token JWT del MH: Se almacena temporalmente en memoria RAM durante aproximadamente 7.5 horas para evitar autenticaciones repetidas. No se persiste en disco.

E. Libro de Créditos (Fiar)

Los datos relativos a los créditos otorgados a clientes (saldos deudas, montos prestados, abonos parciales y fechas de vencimiento) se guardan de forma estrictamente local en la base de datos SQLite del dispositivo. Esta información no se comparte con terceros ni se sincroniza con servidores externos del desarrollador.

F. Procesamiento de Imágenes con Inteligencia Artificial (ML Kit)

Cuando el usuario toma una fotografía de un producto con la cámara de la Aplicación, se ofrece opcionalmente la función de eliminación automática de fondo. Esta función usa Google ML Kit Subject Segmentation, una API de inteligencia artificial local:

  • El procesamiento ocurre completamente en el dispositivo (on-device), de forma local y sin conexión a servidores externos.
  • Las imágenes de productos no se transmiten a Google ni a ningún servidor durante este proceso.
  • Las imágenes resultantes se almacenan exclusivamente en la base de datos local del dispositivo.
  • El uso de esta función es totalmente opcional. El usuario puede usar fotos de productos sin activar la eliminación de fondo.

G. Monitor de Rendimiento Interno (Easter Egg para Desarrolladores)

La Aplicación incluye un módulo de diagnóstico técnico local accesible únicamente mediante una secuencia especial de interacción en la pantalla de Ajustes (toque consecutivo 7 veces sobre el título del encabezado). Este módulo está diseñado para uso de diagnóstico técnico.

  • Lee métricas del sistema operativo Android: FPS (cuadros por segundo renderizados por la App) y porcentaje de uso de memoria RAM de la Aplicación.
  • Estas métricas se muestran en pantalla en tiempo real y son exclusivamente locales. No se almacenan en base de datos ni se transmiten a ningún servidor.
  • El módulo también puede liberar el caché de imágenes de la App desde el propio dispositivo, sin ninguna comunicación externa.

H. Notificaciones Locales

La Aplicación puede mostrar notificaciones locales en el dispositivo (sin pasar por servidores externos) para alertar sobre: nuevos encargos o pedidos recibidos desde el catálogo web, vencimiento próximo de la licencia de uso, productos con stock bajo, alertas de deudas/créditos vencidos y metas de ventas cumplidas. Estas notificaciones son generadas y mostradas completamente en el dispositivo por el sistema operativo Android, sin involucrar servidores de notificaciones push externos.

I. Datos que NO recopilamos

  • Ubicación geográfica (GPS): La Aplicación no rastrea, solicita ni almacena coordenadas de ubicación del usuario bajo ninguna circunstancia.
  • Contactos del teléfono o sistema: No se accede a la agenda de contactos del dispositivo ni del equipo.
  • Micrófono ni audio: No se graban ni procesan conversaciones ni sonidos.
  • Fotos, videos o archivos personales: La cámara se usa exclusivamente para escanear códigos de barras o capturar imágenes de productos del catálogo comercial. En ningún momento se accede a galerías privadas ni archivos personales.

J. Integración con Google Drive (Copias de Seguridad en la Nube)

VendlyPOS (en sus ediciones Desktop y Mobile) ofrece una función opcional de copias de seguridad automáticas y manuales en Google Drive, permitiendo al comerciante resguardar la base de datos de su negocio frente a incidentes de hardware.

  • Alcance solicitado: https://www.googleapis.com/auth/drive.file.
  • Propósito estricto y delimitado: Este permiso se utiliza exclusivamente para crear una carpeta designada (denominada VendlyPOS_Backups) en la unidad del usuario y subir/descargar copias de seguridad de la base de datos del sistema (archivos comprimidos y protegidos con cifrado).
  • Aislamiento total de archivos personales: Conforme a las directivas de Google para el alcance drive.file, VendlyPOS únicamente puede acceder, ver y modificar los archivos creados directamente por la propia aplicación. VendlyPOS NO tiene acceso, no puede visualizar, no lee, no altera ni elimina ningún otro archivo, documento, foto o carpeta preexistente en la cuenta de Google Drive del usuario.
  • Control del usuario y revocación: La vinculación con Google Drive es 100% voluntaria. El usuario puede desvincular su cuenta en cualquier momento desde los ajustes del sistema, o revocar el acceso directamente desde el panel de seguridad de su cuenta de Google en myaccount.google.com/permissions.

K. Autenticación e Identidad con Google (Google Sign-In / OAuth 2.0)

VendlyPOS permite vincular opcionalmente una cuenta de Google para:

  • Validar la titularidad del catálogo web: Asociar de forma segura la tienda con el catálogo público en línea, evitando suplantaciones de identidad.
  • Recuperación administrativa de acceso: Permitir al propietario del negocio restablecer credenciales administrativas maestras en caso de extravío del PIN o contraseña.
  • Alcance solicitado: openid, email y profile.
  • Tratamiento de datos: Únicamente se lee la dirección de correo electrónico y el identificador de cuenta de Google para verificar identidad. No se almacena la contraseña de Google ni se accede a correos de Gmail, contactos ni servicios adicionales.

Declaración de Uso Limitado de las APIs de Google (Google API Services User Data Policy):
El uso y la transferencia que hace VendlyPOS de la información recibida de las APIs de Google a cualquier otra aplicación se apegan estrictamente a la Política de Datos de Usuario de los Servicios de las API de Google (Google API Services User Data Policy), incluidos los requisitos de Uso Limitado (Limited Use). Los datos obtenidos a través de las APIs de Google nunca se transfieren a terceros (salvo lo estrictamente necesario para brindar la funcionalidad de respaldo solicitada por el usuario), no se utilizan para publicidad ni son procesados por inteligencias artificiales para entrenamiento.

2. Permisos del Dispositivo y su Justificación

La Aplicación solicita únicamente los permisos estrictamente necesarios para su funcionamiento. A continuación se detalla cada uno con su propósito exacto:

  • Cámara (android.permission.CAMERA)
    Propósito: Activar el módulo lector de códigos de barras integrado en el punto de venta y capturar fotografías de productos para el catálogo. Este permiso es solicitado únicamente cuando el usuario accede a las funciones de escaneo o carga de imagen.
  • Bluetooth clásico (android.permission.BLUETOOTH, maxSdkVersion="30")
    Propósito: Conexión con impresoras térmicas de tickets (ESC/POS) en Android 11 e inferior. Solo aplicable en dispositivos con API ≤ 30.
  • Bluetooth Conectar (android.permission.BLUETOOTH_CONNECT)
    Propósito: Establecer comunicación con la impresora Bluetooth previamente emparejada para emitir comprobantes de pago físicos.
  • Bluetooth Escanear (android.permission.BLUETOOTH_SCAN, usesPermissionFlags="neverForLocation")
    Propósito: Descubrir impresoras térmicas Bluetooth disponibles en el entorno del negocio. El flag neverForLocation confirma explícitamente al sistema que este permiso no se usa para inferir ubicación.
  • Ubicación aproximada (android.permission.ACCESS_FINE_LOCATION, maxSdkVersion="30")
    Propósito: En versiones de Android 11 e inferiores (API ≤ 30), el sistema operativo Android exige este permiso para habilitar el escaneo de dispositivos Bluetooth. Esto es un requisito del sistema operativo, no de VendlyPOS. La Aplicación no recopila, almacena ni transmite coordenadas de ubicación. Este permiso solo aplica a dispositivos con Android ≤ 11; en Android 12 o superior no se solicita.
  • Internet (android.permission.INTERNET)
    Propósito: Verificar el estado de la licencia de uso, sincronizar datos del catálogo, escuchar pedidos en tiempo real en la nube, gestionar respaldos en Google Drive bajo demanda, y —cuando el usuario activa el módulo DTE— comunicarse con el API del Ministerio de Hacienda de El Salvador para la emisión de Documentos Tributarios Electrónicos.
  • Notificaciones (android.permission.POST_NOTIFICATIONS)
    Propósito: Requerido en Android 13+ para permitir el envío de alertas y notificaciones locales inmediatas sobre nuevos pedidos recibidos de la web, productos con stock crítico, alertas de cobranza y cumplimiento de metas comerciales.

Recursos y Permisos en Windows Desktop

La edición de escritorio para Windows opera como una aplicación local independiente y requiere los siguientes accesos en el sistema operativo:

  • Sistema de archivos local: Lectura y escritura restringida a la carpeta de instalación y datos del programa (instance/, backups/) para persistir la base de datos SQLite (store.db), archivos de configuración y respaldos locales.
  • Red local y sockets de comunicación: Apertura de un socket local seguro (localhost:5000) para renderizar la interfaz de usuario y puertos locales para comunicación mDNS/LAN que permite la sincronización bidireccional con terminales Android dentro del mismo establecimiento comercial.
  • Conexión a Internet (HTTPS/TLS): Comunicación saliente cifrada hacia Firebase (validación de licencia), APIs de Google (Google Drive y Google Identity) y servidores del Ministerio de Hacienda de El Salvador (DTE).
  • Controladores de impresión y Spooler de Windows: Envío de trabajos de impresión de tickets hacia impresoras térmicas conectadas por USB, red local (TCP/IP) o el subsistema Spooler de Windows.

3. Uso de la Información

La información recopilada se utiliza exclusivamente para:

  • Operar el sistema de punto de venta: registrar ventas, gestionar inventario y emitir comprobantes.
  • Validar y mantener activa la licencia de uso mediante el device_uuid.
  • Sincronizar datos operacionales con el servidor local del negocio cuando el usuario lo configure.
  • Enviar notificaciones locales administrativas del sistema (alertas de stock bajo, alertas de deudas, pedidos recibidos, avisos de licencia).
  • Emitir Documentos Tributarios Electrónicos (DTE) ante el Ministerio de Hacienda de El Salvador, cuando el operador activa y configura voluntariamente dicha funcionalidad.

No utilizamos la información para: publicidad, perfilado de usuarios, análisis de comportamiento, venta a terceros ni ningún fin distinto a los listados anteriormente.

4. Intercambio de Datos con Terceros

VendlyPOS aplica una política estricta de mínima exposición de datos:

  • No vendemos, arrendamos ni transferimos datos operacionales, inventarios, registros de ventas ni listas de clientes a ninguna entidad externa.
  • Las únicas conexiones salientes autorizadas son:
    • Firebase (Google LLC): Infraestructura de validación de licencias y notificaciones de servicio. Se envía el device_uuid (hash SHA-256, no el identificador físico real) para verificar la licencia. Firebase aplica su propia política de privacidad.
    • Google Drive API (Google LLC): Exclusivamente cuando el usuario activa la sincronización con Google Drive. Los archivos de respaldo de la base de datos se transfieren directamente a la unidad personal del usuario vía HTTPS utilizando el alcance drive.file. Google procesa estos archivos conforme a su Política de Privacidad.
    • Google Identity Services (Google LLC): Para autenticación OAuth 2.0 al validar la identidad del administrador o enlazar el catálogo web, sin recopilación de contraseñas.
    • Ministerio de Hacienda de El Salvador (api.dtes.mh.gob.sv): Solo cuando el usuario activa y configura el módulo DTE. Se transmiten los datos del documento tributario (emisor, receptor, detalle de venta) mediante HTTPS/TLS para cumplir con la obligación legal de emisión electrónica de comprobantes fiscales. El MH aplica su propia política institucional.
    • Servidor local del negocio (LAN/mDNS): Sincronización de datos entre dispositivos del mismo establecimiento (Desktop y terminales móviles). El flujo de datos cifrado nunca abandona la red interna del local comercial. Su configuración es responsabilidad del usuario.

5. Almacenamiento y Seguridad de los Datos

La protección de la información comercial es una prioridad de diseño en VendlyPOS en ambas plataformas:

  • Almacenamiento local aislado: En Android, todos los datos operacionales se almacenan en la base de datos SQLite dentro del almacenamiento aislado de la aplicación (app-specific storage), inaccesible para otras aplicaciones. En Windows Desktop, la base de datos (store.db) se hospeda localmente en la carpeta del sistema con control de acceso por permisos de usuario del sistema operativo.
  • Cifrado de credenciales y secretos: En Android, las credenciales sensibles (PIN, claves MH, tokens) se protegen mediante FlutterSecureStorage con el Android Keystore System (cifrado AES respaldado por hardware). En Windows Desktop, los tokens de sesión de Google Drive y credenciales sensibles se resguardan cifrados mediante criptografía simétrica (Fernet) vinculada a identificadores criptográficos del hardware o variables de entorno del sistema.
  • Protección contra copias no autorizadas: En Android, la opción android:allowBackup="false" está habilitada en el manifiesto, lo que impide que el sistema realice copias de seguridad automáticas no controladas en la nube de Google, garantizando que los respaldos en la nube solo ocurran cuando el usuario lo solicite explícitamente a través del módulo de Google Drive.
  • Cifrado en tránsito: Todas las conexiones de red externas (Firebase, Google APIs, Ministerio de Hacienda) utilizan estrictamente HTTPS/TLS con validación de certificados.

Nota de seguridad: El operador del negocio es el custodio y responsable de la seguridad física del dispositivo y del equipo de escritorio. Se recomienda configurar bloqueo de pantalla, contraseñas seguras y cifrado de unidad (BitLocker en Windows / cifrado de dispositivo en Android).

6. Retención y Eliminación de Datos

Todos los registros operacionales permanecen almacenados en el dispositivo del usuario hasta que:

  • El operador los elimine manualmente desde las herramientas internas de la Aplicación.
  • El usuario desinstale completamente la Aplicación, lo que elimina todos los datos locales.

No conservamos copias de seguridad de datos comerciales en servidores en la nube. El device_uuid (hash SHA-256) asociado a una licencia puede ser solicitado para su eliminación del servidor Firebase contactando al soporte técnico.

7. Protección de Menores de Edad

VendlyPOS es una aplicación empresarial (B2B) diseñada exclusivamente para uso por adultos en el contexto de la gestión comercial de un negocio. La Aplicación:

  • No está dirigida a menores de 13 años (o la edad mínima digital aplicable en la jurisdicción del usuario).
  • No recopila intencionalmente información de menores de edad.
  • Si un operador tiene motivos para creer que se han recopilado datos de un menor sin consentimiento, debe contactar de inmediato con el equipo de soporte para solicitar la eliminación de dicha información.

8. Derechos del Usuario sobre sus Datos

Como usuario de VendlyPOS, tiene derecho a:

  • Acceder a sus datos locales directamente desde la Aplicación en cualquier momento.
  • Corregir o eliminar datos operacionales (productos, clientes, ventas, créditos) desde las funciones internas de la Aplicación.
  • Solicitar la eliminación del device_uuid del servidor de licencias contactando al equipo de soporte.
  • Exportar sus datos comerciales mediante las funciones de copia de seguridad incluidas en la Aplicación.
  • Desinstalar la Aplicación en cualquier momento, lo que elimina todos los datos locales del dispositivo de forma permanente.
